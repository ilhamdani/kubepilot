Architecture

KubePilot is an Electron app split into three processes with one typed bridge:

ProcessResponsibility
mainKubeconfig parsing, HTTP and WebSocket clients, watches, log streams, exec sessions, port-forward children
preloadOne contextBridge object exposing typed calls and event subscriptions
rendererReact UI, list cache, dock, editor — no Node access

The Kubernetes client is written directly against node:https, node:http and ws rather than using a client library. That keeps the main bundle small and makes reconnect behaviour explicit: watches are line-buffered NDJSON with resourceVersion tracking and exponential backoff. 

src/
  main/
    kube/
      config.ts    kubeconfig + exec credential plugins
      client.ts    HTTP/WS client, watch, exec, logs, apply
      backend.ts   ClusterBackend interface
      live.ts      real cluster
    ipc.ts         every channel in one place
  preload/         contextBridge surface
  renderer/        React + Zustand
  shared/          DTOs shared by all three

LiveBackend implements that interface over the Kubernetes API, so the UI has no idea whether it is talking to a single-node Docker Desktop cluster or a production control plane.

Files & data

KubePilot writes exactly one file, in Electron's per-user data directory:

%APPDATA%\KubePilot\kubepilot-settings.jsonTheme, metrics toggle, extra kubeconfig paths, display names, pinned hotbar items

Kubeconfig files are read, never modified. Credentials obtained from exec plugins are cached in memory only, and dropped when the app exits.

Privacy No telemetry, no analytics, no update pings. The only network traffic is to the API servers you connect to, plus whatever your own credential plugin runs.

Troubleshooting

SymptomCause and fix
No clusters listed Nothing matched KUBECONFIG or ~/.kube/config. Add the file under Preferences → Kubeconfig files.
Cluster shows a red dot Hover for the message. A 401 usually means an expired token from an exec plugin — reconnect to re-run it.
Some kinds are empty RBAC. A 403 on discovery is reported per kind rather than failing the whole cluster.
metrics unavailable metrics-server is not installed. Columns fall back to requests and limits.
Terminal never connects The API server or a proxy may not allow WebSocket upgrades on /exec. Try kubectl exec against the same pod.
Port forward fails immediately Port forwarding shells out to kubectl; make sure it is on PATH.
macOS: “KubePilot is damaged” or “cannot be verified” Gatekeeper on an unsigned build. Right-click the app → Open, or run xattr -cr /Applications/KubePilot.app to clear the quarantine flag.
Blank window after an update Delete %APPDATA%\KubePilot (~/Library/Application Support/KubePilot on macOS) to reset settings and cache, then relaunch.

Known limits

  • No Helm release management yet.
  • No CRD schema validation in the YAML editor — it is YAML highlighting, not a schema.
  • The UI does not hide actions your RBAC forbids; the API server returns the error.
  • Single window, single instance.
  • Windows and macOS are packaged; Linux is not configured yet.
  • Testing is a live-cluster suite rather than unit tests: node tools/e2e-live.mjs drives the running app over the DevTools protocol and exercises 30 surfaces (connect, discovery, CRUD, watch, logs, exec, port-forward, metrics). It needs a reachable cluster and a launch with --remote-debugging-port=9222.
