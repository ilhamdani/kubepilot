Getting started

KubePilot connects to the contexts already in your kubeconfig — there is nothing to seed or configure first. This page takes you from install to a working cluster view.

Requirements

ItemNeeded for
Windows 10/11 x64The packaged installer
Node 22+Running from source
A kubeconfigConnecting clusters — ~/.kube/config is read automatically
Kubernetes 1.24+Server-side apply, metrics.k8s.io, exec

Install the app

  1. Download KubePilot-0.1.0-x64-setup.exe from the releases page.
  2. Run it. The install is per-user, so no administrator prompt is required.
  3. Pick a directory, finish, and launch KubePilot.

The installer is unsigned, so SmartScreen will show a warning the first time. Choose More info → Run anyway, or build from source if you would rather not trust a binary.

Run from source

git clone https://github.com/kubepilot/kubepilot
cd kubepilot
npm install
npm run dev

Other scripts:

npm run devDev server with hot reload for the renderer
npm run buildCompile main, preload and renderer into out/
npm run typecheckType-check the whole project
npm run distBuild the Windows installer into dist/
npm run iconRegenerate build/icon.png
Note The packaged app and the dev server keep separate settings. If you switch between them, expect to re-add kubeconfig files.

Connect a cluster

KubePilot reads the same files kubectl does, in this order:

  1. Every path in the KUBECONFIG environment variable (path-list separated).
  2. ~/.kube/config.
  3. Any additional files you add under Preferences → Kubeconfig files.

Every context in those files becomes a cluster in the left rail. Authentication supports client certificates, bearer tokens, basic auth and exec credential plugins (EKS, GKE, AKS and friends), with the plugin's token cached until shortly before it expires. 

# see what KubePilot will pick up
kubectl config get-contexts

# point it at a non-default file for one session
KUBECONFIG=/path/to/config npm run dev

Your first five minutes

  1. Open Pods under Workloads. Note the restarts and ready columns.
  2. Double-click a row to open the details drawer, then the Events tab.
  3. Open Logs from the drawer's Actions block and watch the stream.
  4. Open Terminal and run ls — that is a real exec session.
  5. Press Ctrl + K and type node to jump to Nodes.
